
# actionable error messages and diagnostics (Requirement)
## Description
Errors name the failing input and the cause; --debug gives details for diagnosis, and stdout stays clean for reports.


## Tags
quality

## Documentation
### Scenario

A user passes a malformed SBOM or policy file, or a lookup fails.

### Measure

Errors are typed and carry a friendly message instead of a stack trace. Diagnostics go to stderr, so report output on stdout can be piped. Inferred from the code, not stated as a requirement.

### Quality attribute

Usability and analysability.
