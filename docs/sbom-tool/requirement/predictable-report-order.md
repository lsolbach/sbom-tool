
# predictable report ordering (Requirement)
## Description
Reports list vulnerabilities by severity and license counts in a defined order.


## Tags
quality

## Documentation
### Scenario

A user compares reports or reads the most important findings first.

### Measure

Vulnerabilities per component are sorted by severity, most severe first (application.report). The license summary is sorted by count, then name (adapter.report.markdown). Other lists are not known to be sorted, so full determinism of all output is not claimed. Inferred from the code.

### Quality attribute

Usability and predictability.
