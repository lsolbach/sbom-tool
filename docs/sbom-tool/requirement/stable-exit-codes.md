
# stable, distinct exit codes (Requirement)
## Description
The process exit code tells success, policy violation, runtime error and usage error apart.


## Tags
quality

## Documentation
### Scenario

A CI job decides from the exit code whether to fail the build, and whether the failure is a policy violation or a broken run.

### Measure

Exit code 0 is success, 1 a policy violation, 2 a runtime or data error and 3 a CLI usage error or failed --validate (adapter.ui.cli). These codes are a public contract. Inferred from the code, not stated as a requirement.

### Quality attribute

Reliability and operability.

## Implementing Decisions
| Decision | Description |
|---|---|
| [separate exit codes per failure category](../../sbom-tool/decision/separate-exit-codes-per-failure-category.md) | Split the CLI's exit code for usage errors from the one for --fail-on-violations policy violations, which previously both exited 1; usage errors, policy violations and runtime/data errors now each have their own code (0/1/2/3, see dev/plans/cli-error-codes.md), forming a stable contract for CI/CD consumers. |
