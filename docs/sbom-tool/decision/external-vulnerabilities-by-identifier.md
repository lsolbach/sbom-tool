
# keep live-lookup vulnerabilities outside the SBOM documents, keyed by purl (Decision)
## Description
Vulnerabilities from live lookups are stored in the repository state (:external-vulnerabilities, purl to canonical vulnerability records) and merged per component, not injected into a synthetic SBOM document.


## Tags
architecture

## Documentation
### Context

A vulnerability embedded in an SBOM refers to component ids that are only meaningful within that document, so vulnerabilities are scoped per document. A live lookup is queried per purl and has no document (goal live-vulnerability-lookup).

### Options

1. Wrap lookup results in a synthetic SBOM document.
2. Keep them in separate repository state keyed by purl and merge them per component.

### Decision

Option 2. The repository state holds :external-vulnerabilities (purl to canonical vulnerability records).
Consolidating a component's vulnerabilities merges them in and deduplicates by id.

### Consequences

Reports, markdown rendering and policy evaluation treat both origins identically, and provenance stays in the per-vulnerability source field.
The merge and the repository union have to know about the second origin.
The proposed NVD adapter (dev/plans/nvd-vulnerability-adapter.md) would extend the key space with CPEs, disjoint from purls.
