
# run remote lookups with bounded concurrency, batching and per-run deduplication (Decision)
## Description
Vulnerability adapters resolve each distinct identifier at most once per run, batch where the API allows, and run requests on a fixed-size thread pool.


## Tags
crosscutting concept

## Documentation
### Context

A real SBOM has hundreds of components, and the sources offer different capabilities and rate limits (deps.dev has no batch endpoint, OSV has a batch endpoint, GitHub has an hourly rate budget). Cross-run caching is a non-goal (no-cross-run-caching).

### Options

1. Sequential requests. 2. Unbounded parallelism (pmap or a thread per request). 3. A fixed-size pool with batching and deduplication within the run.

### Decision

Option 3. Each adapter deduplicates identifiers, chunks them to the API limits and uses a local bounded-pmap helper, a fixed-size thread pool that returns results in input order.

### Consequences

Runs finish in reasonable time without flooding the services. The helper is intentionally duplicated in the osv, deps-dev and github-advisory adapters rather than shared, so a fix has to be applied three times. Concurrency limits are constants in each adapter.
