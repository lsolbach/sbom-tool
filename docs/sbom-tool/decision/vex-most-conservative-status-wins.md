
# resolve conflicting VEX statements to the most conservative status (Decision)
## Description
VEX statements are applied only via an explicit --vex-path; when several match, affected beats under-investigation beats fixed beats not-affected, so a stale not-affected claim cannot hide an affected one.


## Tags
solution strategy

## Documentation
Also: only not-affected and fixed suppress a vulnerability from the blocking report and exit code, and only for components a statement actually names. A malformed VEX file the user pointed at fails loudly, unlike live lookups. Evidence: dev/plans/vex-openvex-adapter.md, domain/vex.clj.
