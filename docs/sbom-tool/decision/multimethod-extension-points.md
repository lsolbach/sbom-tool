
# extend input and output formats through multimethod extension points (Decision)
## Description
The application layer defines multimethods (repository/read-sboms, read-policies, read-vulnerability-sources, template/render); adapters register formats and sources with defmethod, so the core knows neither formats nor I/O.


## Tags
architecture

## Documentation
### Context

Clean Architecture requires the core to know neither SBOM formats nor I/O (decision clean-architecture-layering), while the tool must read several input formats (goal multi-format-input), render several output formats (multi-format-output) and query several vulnerability sources (live-vulnerability-lookup), with more expected.

### Options

1. Multimethods defined in the application layer, implemented by adapters.
2. Format dispatch inside the core or the CLI (cond/case on the format).
3. Protocols or records passed in as dependencies.

### Decision

Option 1. The application layer owns the dispatch point and the adapters register with defmethod.

### Consequences

A new format or source is an additive adapter namespace plus a CLI option value, and the core stays unchanged. The dependency points inward. Dispatch values are open keywords, so a typo surfaces only at runtime. The CLI stays the composition root and must require every adapter for its defmethods to be registered.
