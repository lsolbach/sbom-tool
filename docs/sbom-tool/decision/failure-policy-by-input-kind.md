
# fail loudly on user-supplied inputs, degrade gracefully on remote lookups (Decision)
## Description
A file the user names explicitly (SBOM, policy, VEX, SPDX list, key file) that is missing or malformed aborts the run; a failed remote lookup or an empty input directory only warns.


## Tags
crosscutting concept

## Documentation
### Context

A CI gate must not silently ignore its own inputs, but a network lookup the user did not directly name can fail for reasons outside the user's control (goals ci-gate, live-vulnerability-lookup).

### Options

1. Abort on every failure. 2. Warn and continue on every failure. 3. Distinguish by where the input comes from.

### Decision

Option 3. Explicit local inputs are as much 'the user's input' as an SBOM file and fail with a typed exception. Live vulnerability lookups (chunk or request level) warn once and resolve to no additional vulnerabilities, and an empty input directory only warns. This generalizes decision opt-in-fail-soft-live-lookup and the VEX rule in vex-most-conservative-status-wins.

### Consequences

Predictable behavior per input kind. Known weakness: a degraded lookup is indistinguishable from 'no additional vulnerabilities' in the report, so a gate can pass on incomplete data (open idea in dev/ideas.md).

### Evidence
