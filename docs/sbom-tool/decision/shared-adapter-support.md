
# share the vulnerability adapters' HTTP infrastructure in one adapter-internal namespace (Decision)
## Description
PROPOSED: the osv, deps-dev and github-advisory adapters use one shared support namespace for HTTP calls, key reading, bounded concurrency and warnings.


## Tags
solution strategy

## Documentation
### Status

Proposed. Not accepted; only the maintainer accepts it.

### Context

The three vulnerability adapters duplicate their HTTP client, error handling, key-file reading, bounded-pmap and warn (risks duplicated-adapter-infrastructure, duplicated-bounded-pmap, duplicated-warn-helpers). The open security findings (risks no-network-timeouts-or-size-limits, pagination-url-not-pinned-to-host, debug-println-to-stdout) and the proposed requirements bounded-network-calls and credentials-only-to-own-service are cross-cutting and would otherwise be fixed three times. The plans chose duplication earlier (decision bounded-concurrent-lookups). Layering is decided in clean-architecture-layering.

### Options

1. Do nothing: keep three copies and fix each one.
2. One shared support namespace inside the adapter layer (for example adapter.http), used by the vulnerability adapters.
3. Move the helpers into the application layer.

### Decision (proposed)

Option 2. A single place sets the timeouts and the response size limit, keeps credentials to their own host, reads key files and prints diagnostics to stderr. Option 3 is not recommended: the helpers are I/O and belong in the adapter layer. Option 1 is cheapest today but multiplies every future fix and every new adapter (NVD).

### Consequences

Benefits: one fix point, smaller adapters, a consistent failure mode (a timeout becomes a failed lookup). Costs: a first dependency between adapter namespaces, which needs a sentence in the layering rules in AGENTS.md (a layer boundary change, so the maintainer decides it, tier 3). It supersedes the duplication stated in the consequences of bounded-concurrent-lookups, which stays as written until this decision is accepted. Reversible. Babashka compatibility must be kept (requirement jvm-and-babashka-portability).

### Evidence

adapter/vulnerability/osv.clj, deps_dev.clj, github_advisory.clj at commit 5279795; architecture and security assessments of this date.
