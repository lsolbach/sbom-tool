
# configure through CLI options and EDN files, and keep API keys out of the command line (Decision)
## Description
Behavior is set by CLI options and EDN policy files validated with clojure.spec, with bundled defaults; API keys come from an EDN file or an environment variable, never from an option value.


## Tags
crosscutting concept

## Documentation
### Context

Policies must be configurable (goal configurable-policy). Live lookups may need API keys (goal live-vulnerability-lookup), which must not leak into shell history, process listings, logs or reports.

### Options

1. Keys as CLI option values. 2. Environment variables only. 3. A key file path option with an environment variable as fallback.

### Decision

Option 3 for keys: -K/--osv-api-key-file and -G/--github-advisory-api-key-file name an EDN file with {:api-key ...}, falling back to OSV_API_KEY and GITHUB_ADVISORY_API_KEY. Policy files are EDN, validated against a spec with a message naming the file, and a bundled default policy applies when no path is given. The SPDX license list is a file option with a bundled snapshot as default.

### Consequences

Keys never appear in the command line, and the README advises against committing key files. Policy errors are reported precisely, but policy files, key files and option names are public contracts (changes are tier 3). Network use needs explicit opt-in, so offline runs need no keys.

### Evidence

adapter/policies.clj (spec validation, bundled defaults in resources/policy), adapter/vulnerability/osv.clj and github_advisory.clj (key resolution), adapter/license/spdx.clj, adapter/ui/cli.clj options.
