
# keep provenance and report disagreements instead of silently resolving them (Decision)
## Description
Merged components keep their sources and a :conflicts map where source documents disagree, and every report carries it; each vulnerability keeps its own source.


## Tags
crosscutting concept

## Documentation
### Context

One real-world component is described by several SBOM documents that may disagree (goal consolidate-components), and vulnerabilities come from SBOMs, live databases and VEX statements (goal vulnerability-reporting). Compliance reviewers need to see where a statement came from.

### Options

1. Pick one value per field (first or last wins) and drop the rest. 2. Merge and keep the disagreement visible. 3. Reject inputs that disagree.

### Decision

Option 2. domain.component computes :conflicts (field to the distinct non-blank values) and :sources when merging components; application.report/with-provenance copies them into every report row; each vulnerability carries ::sbom/source with its origin.

### Consequences

Reports stay traceable and nothing is silently overwritten, at the cost of larger report data and consumers that must handle :conflicts. Unidentified components are never merged automatically (non-goal no-automatic-unidentified-merge).

### Evidence

domain/component.clj (scalar-conflicts, merge), application/report.clj (with-provenance), adapter/vulnerability/*.clj (::sbom/source).
