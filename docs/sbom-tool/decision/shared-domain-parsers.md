
# implement purl and CVSS parsing once in the domain, without a library (Decision)
## Description
Package URL parsing and CVSS v2/v3 base scoring are small hand-written domain namespaces shared by all vulnerability adapters, not private copies per adapter or a third-party dependency.


## Tags
architecture

## Documentation
### Context
Every vulnerability adapter must interpret purls (to build queries) and many sources deliver a CVSS vector instead of a severity (to rate findings). The project had no purl parser, and the first adapter carried a private one.

### Options
1. A third-party purl or CVSS library.
2. One small hand-written parser per concept in the domain layer, shared by all adapters.

### Decision

option 2. domain.purl and domain.cvss are pure domain namespaces used by all vulnerability adapters.

### Consequences

logic is tested once, adapters depend inward on the domain only, and the dependency footprint stays small. The project owns spec conformance, e.g. CVSS rounding rules, and supports only v2 and v3 for now (v4 is proposed in dev/plans/cvss-v4-vector-parser.md).
