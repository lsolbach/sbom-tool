
# GitHub pagination URL is followed with the API token and no host check (Risk)
## Description
The rel=next URL from the Link header is requested with the same headers, including the Authorization bearer token, without checking scheme or host.


## Documentation
### Description

adapter.vulnerability.github-advisory/parse-link-header returns the next URL from the response and fetch-advisories requests it with the original headers. Only a response from api.github.com over TLS can supply it, and the default HttpClient does not follow redirects, so exploitation needs a compromised or impersonated endpoint. Found in the security assessment at commit 5279795; confidence medium.

### Impact

The API key could be sent to a host other than api.github.com.

### Mitigation

Accept the next URL only if its scheme is https and its host is api.github.com (see requirement credentials-only-to-own-service). Not started.
