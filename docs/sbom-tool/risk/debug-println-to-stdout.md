
# leftover debug println writes request URLs to stdout (Risk)
## Description
The osv, deps-dev and github-advisory adapters print 'Fetching URL: ...' to stdout, which pollutes report output and logs package names.


## Tags
technical debt

## Documentation
### Description

adapter.vulnerability.deps-dev/fetch-json, adapter.vulnerability.github-advisory/fetch-page and adapter.vulnerability.osv/fetch-json and post-json call (println "Fetching URL:" url). This is a leftover debug statement, not intended behavior. Found in the security assessment at commit 5279795; confidence high. The adapters' warn helpers do write to stderr.

### Impact

Report output on stdout (edn, json, markdown) is corrupted when a live source is used, so it cannot be piped reliably. The URLs contain package names and versions, which end up in captured CI logs. It contradicts the requirement actionable-diagnostics and the decision diagnostics-on-stderr.

### Mitigation

Remove the statements, or send them to stderr behind --debug, ideally through the shared diagnostics function proposed in duplicated-warn-helpers. Not started.
