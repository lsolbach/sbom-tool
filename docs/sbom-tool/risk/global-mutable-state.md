
# application state is one global atom (Risk)
## Description
repository/state is a single atom that adapters fill and every report function reads implicitly, which hides data flow and blocks library use.


## Tags
technical debt

## Documentation
### Description

application.repository/state is (atom {}). Adapters write to it with swap!, and the report functions take no arguments and read it. The order of calls in adapter.ui.cli/initialize-state matters, and tests must reset the global state. Domain functions, in contrast, take their inputs explicitly. Found in the architecture assessment at commit 5279795; confidence high.

### Impact

Hidden coupling between adapters and reports. A second run in the same process (REPL, library use) sees the first run's state, and tests cannot run in parallel. The cost is low while the tool is a one-shot CLI.

### Mitigation

Return data from the adapters and let the CLI assemble an explicit state map that is passed to the report functions (changes internals only, not the public contracts). Or accept the simplification and keep this entry as its record. Open decision for the maintainer.
