
# HTTP calls have no timeouts and no response size limit (Risk)
## Description
The vulnerability adapters use a default HttpClient without connect or request timeout and read whole response bodies, so a stalled endpoint hangs the run.


## Documentation
### Description

osv, deps-dev and github-advisory create HttpClient/newHttpClient and send requests without a timeout. Bodies are read fully as strings, and the futures in bounded-pmap are awaited without a timeout. Found in the security assessment at commit 5279795 (osv only skimmed); confidence high for github-advisory and deps-dev.

### Impact

A stalled, slow or hostile endpoint or proxy blocks the process indefinitely, which is a denial of service for a CI job. Very large responses can exhaust memory.

### Mitigation

Set connect and request timeouts, treat a timeout as a failed lookup (see failed-lookup-looks-like-clean-result) and cap the response size (see requirement bounded-network-calls). Not started.
