
# rate limits and network environments of external services (Risk)
## Description
Rate limits, throttling and restricted networks can slow or break live lookups on large SBOMs or in CI.


## Documentation
### Description

deps.dev has no batch endpoint and no documented hard limit, so the concurrency default is a guess. GitHub's unauthenticated budget is shared with anything else on the same IP or token. Restrictive networks can fail on the JVM trust store. The proposed NVD adapter would take about three minutes for 30 CPEs without a key.

### Impact

Slow runs, failed chunks that are silently dropped (see failed-lookup-looks-like-clean-result), and flaky CI.

### Mitigation

Bounded concurrency and batching (decision bounded-concurrent-lookups), optional API keys, --debug for diagnosis. No cross-run cache (non-goal no-cross-run-caching).
